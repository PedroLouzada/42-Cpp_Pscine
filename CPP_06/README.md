# CPP06 — C++ Casts

<img src="https://upload.wikimedia.org/wikipedia/commons/1/18/ISO_C%2B%2B_Logo.svg" width="150" />

## 🧩 About the Project

**CPP06** is the seventh module of the C++ series at 42.
This module explores how C++ converts values, reinterprets memory representations, and discovers the real type hidden behind a polymorphic interface.

The exercises move through three very different kinds of casts. First, textual scalar literals are parsed and converted into multiple primitive types. Then, a pointer is transformed into an integer representation and restored without losing its identity. Finally, runtime type information is used to distinguish between objects derived from the same base class.

The type system stops being invisible and becomes something that must be handled deliberately. 🔍

---

## 🧠 What I Learned

* How the main C++ casting operators differ from traditional C-style casts.
* Using `static_cast` for explicit conversions between compatible scalar types.
* Parsing textual representations of `char`, `int`, `float`, and `double`.
* Handling special floating-point values such as `nan`, `nanf`, `+inf`, `-inf`, `+inff`, and `-inff`.
* Distinguishing between impossible conversions and valid but non-displayable characters.
* Designing utility-style classes that cannot be instantiated and expose only static operations.
* Using `reinterpret_cast` to convert between pointers and integer representations.
* Understanding `uintptr_t` as an unsigned integer type capable of storing a pointer value.
* Preserving pointer identity across a serialization and deserialization round trip.
* Using `dynamic_cast` to inspect the real type of an object through a polymorphic base class.
* Understanding the difference between failed pointer casts and failed reference casts.
* Why a polymorphic base class needs a virtual destructor.

## ⚙️ Exercises

### ex00 — Conversion of scalar types 🔄

> Parsing literals and converting them into primitive C++ types.

Implements a non-instantiable `ScalarConverter` class containing the static method:

```cpp
static void convert(const std::string& literal);
```

The program receives one literal as a command-line argument, determines its original scalar type, and prints its representation as:

* `char`
* `int`
* `float`
* `double`

The converter recognizes regular numeric values, single displayable characters, decimal representations, floating-point suffixes, and special pseudo-literals.

Conversions that cannot be represented are reported as impossible, while valid character values outside the printable range are reported as non-displayable.

This exercise combines parsing, validation, formatting, numeric limits, and explicit type conversion into one controlled pipeline.

---

### ex01 — Serialization 📦

> Converting a pointer into an integer representation and back again.

Introduces a simple `Data` structure and a non-instantiable `Serializer` class with two static methods:

```cpp
static uintptr_t serialize(Data* ptr);
static Data* deserialize(uintptr_t raw);
```

`serialize()` uses `reinterpret_cast` to transform a `Data*` into a `uintptr_t`.
`deserialize()` performs the inverse conversion and restores the pointer.

The purpose is not traditional file or network serialization. Instead, the exercise demonstrates that a pointer's raw address can be represented as an integer and reconstructed without changing the object it references.

After the round trip, the deserialized pointer must point to the exact same `Data` object and preserve access to its original value.

---

### ex02 — Identify real type 🎭

> Runtime type identification through a polymorphic base class.

Defines a polymorphic `Base` class and three empty derived classes:

* `A`
* `B`
* `C`

The `generate()` function randomly creates one of the derived objects and returns it through a `Base*`.

Two overloaded `identify()` functions then determine the object's real type:

```cpp
void identify(Base* p);
void identify(Base& p);
```

The pointer version uses `dynamic_cast` and checks whether the resulting pointer is `NULL`. The reference version relies on exceptions because a failed reference cast throws `std::bad_cast`.

The type must be discovered without using `typeid`.

This exercise shows how runtime polymorphism allows code to recover the concrete type hidden behind a base-class interface.

```bash

cd 42-Cpp_Pscine/CPP_06/ex00

./convert 42
```

## 🔍 Rules & Constraints

* All code is compiled with `-Wall -Wextra -Werror` and the `-std=c++98` flag.
* Conversions must use the appropriate C++ casting operators.
* `ScalarConverter` and `Serializer` must not be instantiable.
* Scalar conversion must handle valid literals, invalid input, pseudo-literals, and non-displayable characters.
* Pointer serialization must preserve the original pointer value.
* `Base` must be polymorphic and have a virtual destructor.
* Runtime identification must use `dynamic_cast`.
* `typeid` cannot be used to identify the derived classes.
* Every dynamically generated `A`, `B`, or `C` object must be properly deleted.
* No memory leaks.

## 💡 Final Thoughts

CPP06 makes type conversions explicit.

The three exercises operate at different levels: values, addresses, and runtime object identities. A scalar cast changes how a value is represented, a reinterpret cast exposes the numerical representation of an address, and a dynamic cast asks the runtime whether an object satisfies a particular type relationship.

None of these operations are interchangeable, even though they are all called casts.
