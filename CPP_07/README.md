# CPP07 — C++ Templates

<img src="https://upload.wikimedia.org/wikipedia/commons/1/18/ISO_C%2B%2B_Logo.svg" width="150" />

## 🧩 About the Project

**CPP07** is the eighth module of the C++ series at 42.
This module introduces **templates**, allowing functions and classes to operate on different data types without duplicating their implementation.

Instead of writing one function for integers, another for floating-point values, and another for strings, templates describe an operation once and let the compiler generate the required version for each compatible type.

The exercises progress from small generic functions to array traversal and finally to a complete dynamically allocated container.

---

## 🧠 What I Learned

* How to declare and implement function templates.
* How template argument deduction determines the required type from function arguments.
* Creating generic operations that work with built-in types and user-defined classes.
* Understanding that templates still impose requirements on their types, such as supporting comparison or assignment operators.
* Passing template-compatible functions as callbacks.
* Applying the same operation to every element of an array.
* Creating class templates with constructors, destructors, copy constructors, and assignment operators.
* Managing dynamically allocated memory inside a generic container.
* Implementing deep-copy semantics for templated classes.
* Providing const and non-const versions of `operator[]`.
* Protecting indexed access with bounds checking and exceptions.
* Keeping template implementations visible at the point of instantiation.
* Organizing template code between `.hpp` and `.tpp` files.

## ⚙️ Exercises

### ex00 — Start with a few functions 🔁

> Generic implementations of `swap`, `min`, and `max`.

Implements three function templates:

```cpp
template <typename T>
void swap(T& a, T& b);

template <typename T>
T min(T& a, T& b);

template <typename T>
T max(T& a, T& b);
```

`swap()` exchanges two values of the same type.
`min()` returns the smaller value.
`max()` returns the greater value.

When both values compare as equal, `min()` and `max()` return the second argument.

The same implementations are tested with integers and `std::string`, demonstrating that generic code can work with any type that provides the required assignment and comparison operations.

A small exercise, but the first step toward compile-time generic programming.

---

### ex01 — Iter 🔄

> Applying a function to every element of an array.

Implements the `iter()` function template:

```cpp
template <typename T>
void iter(T* array, const size_t length, void (*function)(T&));
```

The function receives:

* A pointer to the first element of an array.
* The number of elements in that array.
* A function that will be called for every element.

Because each element is passed by reference, the callback can either inspect or modify the array.

The implementation is tested with different types and operations, including multiplying integer values, printing elements, and modifying strings.

This exercise shows that an algorithm does not need to know the concrete type of the data it processes. It only needs a valid operation that can be applied to each element.

---

### ex02 — Array 📚

> A generic dynamically allocated array with deep-copy semantics.

Implements the class template:

```cpp
template <class T>
class Array;
```

The class provides:

* A default constructor that creates an empty array.
* A constructor that allocates `n` value-initialized elements.
* A copy constructor.
* A copy-assignment operator.
* A destructor.
* Const and non-const indexed access through `operator[]`.
* A `size()` member function.

Copies must be completely independent. Modifying an element in a copied array cannot change the original array, which requires deep-copy semantics rather than simply copying the internal pointer.

Accessing a negative index or an index greater than or equal to the array size throws `std::out_of_range`.

The implementation is split between `Array.hpp` and `Array.tpp`, keeping the class declaration organized while ensuring that the compiler can still see every template definition.

This exercise combines templates with memory management, exception safety, operator overloading, and the Orthodox Canonical Form.

## 🔍 Rules & Constraints

* All code is compiled with `-Wall -Wextra -Werror` and the `-std=c++98` flag.
* Function and class templates must work with multiple compatible types.
* Template implementations must remain visible when the compiler instantiates them.
* STL containers and algorithms are not used.
* `swap`, `min`, and `max` must operate on two values of the same type.
* `iter()` must apply the supplied function to every element in the given range.
* `Array<T>` must manage its own dynamically allocated storage.
* Array copies must use deep-copy semantics.
* New arrays must be value-initialized.
* Invalid indexed access must throw an exception.
* Every allocation performed with `new[]` must be released with `delete[]`.
* No memory leaks.

## 💡 Final Thoughts

CPP07 replaces type-specific repetition with reusable compile-time abstractions.

The first exercise shows that a simple operation can be shared by unrelated types. The second separates the traversal of a sequence from the action performed on each element. The final exercise demonstrates that an entire resource-owning class can be generated for any compatible type.

Templates do not remove type safety. They allow the compiler to enforce the same design across many types.
